# Comparing the leading submissions

The organizer benchmarks on a Synteq KVM guest with one Xeon Platinum 8260 vCPU, 1,967 MB of RAM, no swap and Ubuntu 24.04 with kernel 6.8. Separate 16-core load generators are in the same datacenter. Scores count simultaneous virtual users. Each user makes several real HTTP requests during a session and sleeps between requests. For example, holding 310,000 users gave Kensac 29,284 requests/s. A five-minute score requires p95 below 500 ms, p99 below one second and fewer than 1% errors. We verified these five leading entries against the organizer’s published leaderboard on November 13. [Published hardware, scoring method and leaderboard](https://github.com/arjaythedev/twelve-dollar-server-challenge/blob/63a9b9ea449e686260bd55e6639a1545db18a407/LEADERBOARD.md)

## Explicit fixed-file slots

A second admission method assigns each newly accepted socket a never-used fixed slot in its bank. Linux can then import a batch and add its ordinary file descriptors to epoll in the same ring submission. A socket may become readable before either completion is consumed. The reactor records that event against the slot generation, publishes the socket once the import and all its watch operations have completed, and keeps every ordinary alias until that point. Exhausted banks return slot allocation to Linux. [Source change against `43adbd7`](explicit-slot/reactor.patch)

## The first HTTP exchange

On Linux 6.8, setting `TCP_QUICKACK=0` on the listening socket after `listen()` let the first HTTP response acknowledge the request. In four paired trials, all 8,192 fresh connections to the scored C server received one standalone ACK. All 8,192 fresh connections to the hinted server received their first response without that extra packet. Every 5,176-byte feed matched the organizer’s golden response. Under mixed load, 67 of 8,192 fresh connections to the hinted server still received the ACK. On established connections with 3–15 seconds between requests, both servers normally combined it with the response. [Per-trial results](ack-results.json)

At 1,000 fresh admissions/s the server’s median CPU cost per first request fell from 134.7 to 119.3 µs over four pairs. At 2,500 admissions/s it changed from 124.8 to 124.0 µs, with two pairs favoring each build. Established clients at 5,000 requests/s cost 46.9 and 49.2 µs respectively. The component test measures packet behavior and process CPU. The capacity comparison uses the complete workload. [CPU measurements and binary identities](ack-results.json)

A fragmented request has no response ready to carry its ACK. With a Nagle-enabled client and a 2 ms gap between writes, the listener hint alone delayed a valid authenticated POST to about 41 ms. The production parser requests an immediate ACK the first time it needs more bytes. The resulting median was 4.17–4.24 ms for two writes, 5.50–5.55 ms for three, and 18.66–19.63 ms for eight. Original medians were 3.37–3.90, 5.52–5.57, and 17.41–19.20 ms. Complete GETs, POSTs and pipelined requests retained their results and the initial packet saving. ### SQLite sibling-page reordering

When SQLite reorders dirty B-tree siblings, three page moves exchange their keys using the reserved lock-byte page as a temporary key. The built-in page cache tracks an upper bound on its resident keys. The temporary key can inflate that bound long after the exchange finishes. The experimental SQLite patch saves the previous bound and restores it after the complete permutation when the temporary key raised it. It keeps all three original moves and their page flags, journal bookkeeping and callbacks. Other page-cache implementations use their original code path. [Patch against the pinned SQLite 3.54.1 amalgamation](experimental-sqlite-sibling-swap.patch)

### Crossing consumed SQLite leaves

The experimental `cd4b88d` reader decodes the post rows or index keys on a pinned SQLite leaf once. After consuming the leaf it positions the live cursor at the boundary and calls SQLite’s normal `Previous` or `Next` once to cross it. On an interior likes-index page, it processes the separator row at its actual ordinal before calling `Next`. The two changes leave SQLite’s parent stack, WAL snapshot and page ownership intact. [Source patch](sqlite-consumed-leaf.patch)

Across six matched pairs, whole-process CPU on the captured mixed HTTP workload fell 0.92% in the median. Four pairs improved. On a separate valid dataset with thousands of likes on recent posts, feed CPU fell 73.45% and point-read CPU fell 24.91%, in all six pairs. The hashed response stream and reopened writes matched the control. The reader passed 42 API checks, 13 differential layouts and 3,067 comparisons to prepared SQL with a debug, address- and undefined-behavior-sanitized SQLite build.
